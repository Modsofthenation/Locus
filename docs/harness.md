# Harness ratchet

Minimum walls for Locus agents. Prompt text is not a substitute for these checks.

| # | Tooth | Where it bites |
| --- | --- | --- |
| 1 | Git walls | Resolve `HEAD` before `git_push`. Refuse force-push in `git_push` and `exec`. Refuse push to `main` / `master` / `trunk` even when autonomous. The guest `git_push` command also checks the current branch. |
| 2 | Exec tripwires | `exec` / `powershell` refuse force-push, `rm -rf`, credential-file names, launching the Locus desktop/AppImage binary (`locus`, `/tmp/.mount_Locus-*`, `Locus-*.AppImage`), and (when `allowHosts` is set, including `[]`) curl/wget off the allowlist. File tools already jail `/workspace`. Host and Cursor CLI shells also drop AppImage mounts from `PATH`. Packaged `locus --help` / subcommands print a GUI hint and exit instead of opening another window. |
| 3 | Repo rules | Load `Locus.md`, `AGENTS.md`, `CLAUDE.md`, and `.locus/rules` into the system prompt (same char budget as other session rules). `Locus.md` is first-party guiding context and loads first. |
| 4 | Hooks | After `file_write` / `apply_patch`, append `npm run lint` output when that script exists. Do not revert the edit. If lint fails because `node_modules` is missing, append a skip note instead of the stack. Before `git_push` / `git_pr`, run the affected workspace `npm test` scripts (including transitive dependents, 10 min total timeout), or the full suite for repository-wide/config changes, unknown Git state, or an unavailable dependency graph, and block the tool if validation fails, putting `FAIL` lines first. Documentation and `.locus-attachments`-only changes skip package tests when the base diff is known. Skip when there is no workspace or script. A malformed primary manifest fails closed; an unreadable dependency graph falls back to the full suite. On Docker agents, chown the bind mount to the host user first so Vite can write `node_modules/.vite-temp`. |
| 5 | Tool args | Validate catalog tools against `TOOL_SCHEMAS` at execute time. Extra properties are allowed. Missing or mistyped required fields return an actionable error. |
| 6 | Typed verdicts | Review sessions must finish with `{ verdict, reasons, risk }`. The parser accepts `PASS`/`FAIL` plus aliases (`APPROVE` → PASS, `REQUEST_CHANGES`/`CHANGES_REQUESTED` → FAIL), case-insensitive risk, JSON buried in mixed prose, `locus-git_pr_*` names, and a `git_pr_review` event fallback. A missing verdict gets one hidden retry, then `needsHuman`. `FAIL` / `risk: high` still sets `needsHuman` (use **Fix with agent** to implement). A clean PASS this turn without `git_pr_get` / `git_pr_loadpath` / `git_pr_comment` / `git_pr_review` also sets `needsHuman` — a guessed PASS cannot ship after the inspect cap. Follow-up chatter after a completed review is not re-gated unless this turn called `git_pr_*` or emitted a new JSON verdict. Other automations are not forced into this JSON. The system prompt always includes the standard review lens. A linked repo may append `reviewPrompt`. |
| 7 | Param permissions | Policy `deny` / `alwaysAsk` / `autoAllow` match entries such as `git_push(branch:locus/*)` and `file_read(path:.env)`. |
| 8 | Blocked actions are loud | Denied tools write a `blocked` trace, set `session.needsHuman`, and fail the automation run (existing notify path). |
| 9 | Regression suite | `packages/shared/src/harness.test.ts` and `apps/server/src/evals/harness.eval.test.ts` cover no push to main, no `.env` read, no force-push, bad tool args, `Locus.md` / `AGENTS.md` load, and verdict parse. |
| 10 | Lean review tools | `REVIEW_TOOLS` is inspect/comment only (no `exec`, write, commit, push, or open-PR). Default for `kind: "review"` and the `pr-reviewer` recipe. Cursor CLI review turns pass `--exclude-tools` for write/edit/shell (and web unless Web is on). |
| 11 | Automation resume | `reuseSession` plus status `error` with a checkpoint rewinds, then continues, instead of throwing "Guest entered an error state." |
| 12 | MCP pin | `McpServerConfig.toolHashes` / `version`. When hashes are non-empty, tools whose description pin does not match are dropped. Empty hashes expose every listed tool. |
| 13 | Ops routing | After four workspace-search rounds on a Grafana/Slack/Jira/Confluence/Linear/incident.io/AWS IAM/Portainer/Figma/Gmail/Calendar/Drive/Sentry prompt without calling those host tools or `mcp_call` / `mcp_code`, inject a hidden routing note. Listing MCP tools does not count as progress. Cursor CLI and Claude Code receive Locus first-party integrations through loopback MCP (`POST /mcp`). Review sessions additionally get `git_pr_*` on the session-scoped server (`POST /mcp/sessions/:sessionId`). Worker Cursor CLI / Claude Code get the same session MCP through a worker-loopback reverse proxy (row 53) instead of the laptop `127.0.0.1` URL. Large Jira/Grafana/Confluence/Linear/incident.io JSON is offloaded with `ok: true. spilled: true` (not silently sliced to 8k, and not marked failed); the offload text forbids exec/curl re-fetch. |
| 14 | Coding harness smoke | `apps/server/src/evals/coding.eval.test.ts` plus `apps/server/fixtures/coding-eval/` run a scripted turn against a failing-test fixture: patch, then the agent `exec`s `npm test`, then `npm test` must pass. A stuck turn that patches a no-op, runs tests that still fail, then talks through the self-correct cap sets `needsHuman`. `packages/shared/src/codingEval.ts` is the pass/fail scorer. Not a substitute for the safety walls. |
| 15 | Repo hooks | `.locus/hooks.json` `PreToolUse` / `PostToolUse` / `Stop`. A failing PreToolUse blocks the tool (same as a failing `npm test` before `git_push`). PostToolUse appends output and does not revert. Stop runs at turn end. Default npm lint/test still run when no matching hook exists. |
| 16 | Plan-mode verification | `/plan` may `exec` tests and read-only commands (`npm test`, `git diff`, `rg`). Mutating exec is refused. |
| 17 | Sticky allow | Needs you **Always allow** (and `locus agent approve --always`) writes a session `autoAllow` entry such as `git_push(branch:locus/*)`. |
| 18 | Typed sub-agents | `spawn_agent` kinds: **explore** (read-only research), **implement** (patch / test, no push), **review** (bugs and missing tests). |
| 19 | Visible compact | A compact boundary is a system message in the thread and `session.lastCompact` on the context meter. Compact messages are stripped from the model prompt. Compact continue re-injects live loop walls: canvas quality/juice/sculpt/adherence/unused/unplayable, coding wander/verify, and review/ops routing. Design/Games/Assets compact continue also re-injects a fresh canvas snapshot (bytes, headline/API, tokens, generic/playable fingerprints) without resetting the turn-start mutate baseline; omitting that snapshot is a leak — the model re-reads `index.html` after a fold. |
| 20 | Structured plan | `/plan` parses **Files** and **Risks** onto the plan card alongside the checklist. Cursor CLI/Cloud `createPlan` todos become the same proposed card (no `/plan` required). |
| 21 | Host-exec jail | Host `exec` / `start_process` refuse paths outside this session's `/workspace` (system bins such as `/usr` stay allowed). |
| 22 | Background process completion | `start_process` PIDs are polled each round. On exit, a hidden nudge with the log tail is injected. |
| 23 | Review loop | Missing review JSON gets one retry (native hidden nudge; Cursor CLI `--resume` with the same contract). After that inspect cap, a guessed PASS still cannot ship: turn end sets `needsHuman` unless this turn called `git_pr_get` / `git_pr_loadpath` / `git_pr_comment` / `git_pr_review`. | 24 | Own-PR review | `git_pr_review` REQUEST_CHANGES / APPROVE that GitHub rejects on the author's PR is retried as COMMENT. The tool args keep the requested event so the verdict parser still sees FAIL / PASS. Do not ask the model to re-post. |

| 26 | Cursor CLI tool traces | Completed Cursor CLI `tool.result` lines store a clipped output snippet (same `detail` as the native loop). Shell JSON with a nonzero `exitCode` is `ok: false`. |
| 27 | Patch file mode | Host/Docker `apply_patch` restores the executable bit after replacing a file (Docker unlinks then writes, which would otherwise drop `+x`). |
| 28 | Typed publish verdicts | `git_push` / `git_pr` test-gate blocks return `status`, `category`, `retryable`, and structured failure details through the session MCP. | 29 | Publish-gate diagnostics | The gate records the workspace plan (including dependency expansion), command, duration, exit code, failure kind, failed-test identifiers, and a clipped head/tail log.
